Rebuild it yourself: a smaller Sitechat, step by step

Reading code teaches you to recognise it; writing it teaches you to explain it, which is what interviews test. This phase walks you through building minichat, a small working version of Sitechat (about 300 lines) in the same order the real project was built. Every file below was written and tested before being put on this page: its 7 tests pass, and its widget was checked in a real browser. After the mini version, a second part lists exercises that grow it towards the real thing, each pointing to the phase that explains it.

How to use this phase

  • Type the code, don't paste it. Typing forces you to read every line; pasting lets your eyes slide past. When something breaks, that's the lesson.
  • After each step, run the tests and answer the step's "explain it" question out loud, as if to an interviewer.
  • Work in a new folder, not inside the Sitechat repo, so you can't break the real project.
  • The mini version needs Python 3.12 and, for the AI steps, an OpenAI key. The tests need no key: they fake the model, exactly like Sitechat's.

Step 3. Models: the shapes of the data

minichat/models.py, the complete file:

from datetime import datetime, timezone

from pydantic import BaseModel, Field


def now() -> datetime:
    return datetime.now(timezone.utc)


class Tenant(BaseModel):
    tenant_id: str
    site_key: str
    display_name: str
    allowed_domains: list[str] = Field(default_factory=list)
    team_email: str = ""


class Message(BaseModel):
    role: str  # "user" or "assistant"
    content: str


class Conversation(BaseModel):
    tenant_id: str
    conversation_id: str
    messages: list[Message] = Field(default_factory=list)
    updated_at: datetime = Field(default_factory=now)


class Fact(BaseModel):
    category: str
    label: str
    value: str


class Chunk(BaseModel):
    chunk_id: str
    tenant_id: str
    heading_path: list[str]
    text: str

    def searchable(self) -> str:
        return " > ".join(self.heading_path) + "\n\n" + self.text


class Lead(BaseModel):
    tenant_id: str
    conversation_id: str
    email: str = ""
    wants_contact: bool = False
    reason: str = ""
    emailed: bool = False

Each class is a Pydantic model: typed fields, validated on creation, convertible to and from JSON. Field(default_factory=list) gives each object its own list. Chunk.searchable() puts the heading path in front of the text, the same trick as the real to_searchable_text.

Explain it: why is the lead a separate model from the conversation? (Phase 4d, §2: personal data with its own retention and access.)

Step 4. Stores behind interfaces

minichat/stores.py:

from abc import ABC, abstractmethod

from minichat.models import Conversation, Fact, Lead, Message, Tenant, now


class TenantStore(ABC):
    @abstractmethod
    def get_by_site_key(self, site_key: str) -> Tenant | None: ...

    @abstractmethod
    def save(self, tenant: Tenant) -> None: ...


class InMemoryTenantStore(TenantStore):
    def __init__(self) -> None:
        self._by_id: dict[str, Tenant] = {}

    def get_by_site_key(self, site_key: str) -> Tenant | None:
        return next((t for t in self._by_id.values() if t.site_key == site_key), None)

    def save(self, tenant: Tenant) -> None:
        self._by_id[tenant.tenant_id] = tenant


class ConversationStore(ABC):
    @abstractmethod
    def get(self, tenant_id: str, conversation_id: str) -> Conversation | None: ...

    @abstractmethod
    def append_turn(self, tenant_id: str, conversation_id: str, user: str, reply: str) -> None: ...


class InMemoryConversationStore(ConversationStore):
    def __init__(self) -> None:
        self._data: dict[tuple[str, str], Conversation] = {}

    def get(self, tenant_id, conversation_id):
        return self._data.get((tenant_id, conversation_id))

    def append_turn(self, tenant_id, conversation_id, user, reply):
        key = (tenant_id, conversation_id)
        convo = self._data.get(key) or Conversation(tenant_id=tenant_id, conversation_id=conversation_id)
        convo.messages += [Message(role="user", content=user), Message(role="assistant", content=reply)]
        convo.updated_at = now()
        self._data[key] = convo


class FactStore:
    """Facts per tenant. In memory here; Firestore in the real project."""

    def __init__(self) -> None:
        self._data: dict[str, list[Fact]] = {}

    def get(self, tenant_id: str) -> list[Fact]:
        return self._data.get(tenant_id, [])

    def save(self, tenant_id: str, facts: list[Fact]) -> None:
        self._data[tenant_id] = facts


class LeadStore:
    def __init__(self) -> None:
        self._data: dict[tuple[str, str], Lead] = {}

    def get(self, tenant_id: str, conversation_id: str) -> Lead:
        key = (tenant_id, conversation_id)
        return self._data.setdefault(key, Lead(tenant_id=tenant_id, conversation_id=conversation_id))

Two stores have abstract interfaces (TenantStore, ConversationStore), so you can add a Firestore version later without touching the rest. To keep minichat short, facts and leads are simple classes; in Sitechat every store follows the full pattern. next((... for ...), None) returns the first match or None. setdefault returns the existing lead or stores and returns a new one.

Explain it: what does @abstractmethod buy you? (Phase 0, §8.12: a class that forgets a method can't even be created.)

Step 5. The model wrapper

minichat/llm.py:

import os

from openai import APIError, OpenAI

MODEL = "gpt-4o-mini"
_client: OpenAI | None = None


class LLMError(Exception):
    """The model could not be reached. Carries a message a visitor can read."""

    def __init__(self, user_message: str) -> None:
        super().__init__(user_message)
        self.user_message = user_message


def _get_client() -> OpenAI:
    global _client
    if _client is None:
        _client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY", ""), timeout=15, max_retries=1)
    return _client


def complete_with_tools(messages: list[dict], tools: list[dict]):
    """One model call. Returns the message object (text or tool calls)."""
    try:
        response = _get_client().chat.completions.create(
            model=MODEL, messages=messages, tools=tools, max_tokens=600
        )
    except APIError as exc:
        raise LLMError("Something went wrong. Please try again.") from exc
    return response.choices[0].message


def embed(texts: list[str]) -> list[list[float]]:
    response = _get_client().embeddings.create(model="text-embedding-3-small", input=texts)
    return [item.embedding for item in response.data]

The only file that talks to OpenAI. The client is built on first use, so importing the module needs no key (tests import it). API failures become LLMError with a message a visitor can read. Real Sitechat goes further: separate messages per error type, a deadline shared by all tool rounds, trimming a cut-off reply, and token counting for a daily budget (Phase 4b, §8).

Explain it: why return the whole message object instead of its text? (Because the caller must tell a tool request from a reply.)

Step 6. Chunking and vector search

minichat/retrieval.py:

import re

from minichat import llm
from minichat.models import Chunk

HEADING = re.compile(r"^(#{1,6})\s+(.*)$")


def chunk_markdown(text: str, tenant_id: str, doc_id: str) -> list[Chunk]:
    """One chunk per heading section, each carrying its heading path."""
    stack: list[tuple[int, str]] = []
    buffer: list[str] = []
    chunks: list[Chunk] = []

    def flush() -> None:
        body = "\n".join(buffer).strip()
        if body:
            chunks.append(Chunk(chunk_id=f"{doc_id}__{len(chunks)}", tenant_id=tenant_id,
                                heading_path=[h for _, h in stack], text=body))
        buffer.clear()

    for line in text.split("\n"):
        match = HEADING.match(line)
        if match:
            flush()
            level = len(match.group(1))
            while stack and stack[-1][0] >= level:
                stack.pop()
            stack.append((level, match.group(2).strip()))
        else:
            buffer.append(line)
    flush()
    return chunks


class InMemoryVectorStore:
    """Vectors per tenant ("namespace"). Pinecone in the real project."""

    def __init__(self) -> None:
        self._data: dict[str, list[tuple[Chunk, list[float]]]] = {}

    def add(self, tenant_id: str, chunks: list[Chunk]) -> None:
        vectors = llm.embed([c.searchable() for c in chunks])
        self._data.setdefault(tenant_id, []).extend(zip(chunks, vectors))

    def search(self, tenant_id: str, query: str, top_k: int = 5) -> list[Chunk]:
        [q] = llm.embed([query])
        scored = [(sum(a * b for a, b in zip(q, v)), c) for c, v in self._data.get(tenant_id, [])]
        scored.sort(key=lambda pair: pair[0], reverse=True)
        return [c for _, c in scored[:top_k]]

chunk_markdown is the heading-stack algorithm from Phase 4c, §3, shortened (no splitting of long sections). The vector store keeps a list of (chunk, vector) per tenant, the in-memory equivalent of a Pinecone namespace, and ranks by dot product, which equals cosine similarity for OpenAI's length-1 vectors. [q] = llm.embed([query]) unpacks a one-item list into q.

Explain it: why must documents and questions use the same embedding model? (Phase 3, §6.)

Step 7. The agent: prompt, facts, extracts, tools

minichat/agent.py, the heart:

import json
import re

from minichat import llm
from minichat.models import Tenant

RULES = """You are the assistant on {name}'s website.
- Help only with questions about {name}. Politely decline anything else.
- Answer only from the information you are given. If it is not there,
  say you don't know and offer to have the team get in touch.
- When the visitor wants the team to follow up, call contact_team.
- Never write out a visitor's email address."""

CONTACT_TEAM = {
    "type": "function",
    "function": {
        "name": "contact_team",
        "description": "Pass the visitor's request to the team, who will follow up by email.",
        "parameters": {
            "type": "object",
            "properties": {"reason": {"type": "string"}},
            "required": ["reason"],
        },
    },
}

EMAIL = re.compile(r"\b[\w.+-]+@[\w-]+\.[\w.-]+\b")
MAX_TOOL_ROUNDS = 3


def generate_reply(tenant: Tenant, conversation_id: str, message: str, stores) -> tuple[str, str]:
    """Returns (reply, the message as stored, with any email removed)."""
    lead = stores.leads.get(tenant.tenant_id, conversation_id)
    found = EMAIL.search(message)
    if found:
        lead.email = found.group(0).lower()
        message = message.replace(found.group(0), "[email provided]")

    messages = [{"role": "system", "content": RULES.format(name=tenant.display_name)}]
    facts = stores.facts.get(tenant.tenant_id)
    if facts:
        lines = "\n".join(f"- {f.category} / {f.label}: {f.value}" for f in facts)
        messages.append({"role": "system", "content": "Verified facts. Use exactly as written:\n" + lines})
    chunks = stores.vectors.search(tenant.tenant_id, message) if stores.vectors else []
    if chunks:
        extracts = "\n\n".join(f"{' > '.join(c.heading_path)}\n{c.text}" for c in chunks)
        messages.append({"role": "system", "content": "Relevant extracts:\n\n" + extracts})
    if lead.email:
        messages.append({"role": "system", "content": "The visitor already gave their email."})
    convo = stores.conversations.get(tenant.tenant_id, conversation_id)
    for m in convo.messages if convo else []:
        messages.append({"role": m.role, "content": m.content})
    messages.append({"role": "user", "content": message})

    for _ in range(MAX_TOOL_ROUNDS):
        reply = llm.complete_with_tools(messages, [CONTACT_TEAM])
        if not reply.tool_calls:
            return reply.content or "", message
        messages.append({"role": "assistant", "content": reply.content,
                         "tool_calls": [tc.model_dump() for tc in reply.tool_calls]})
        for call in reply.tool_calls:
            messages.append({"role": "tool", "tool_call_id": call.id,
                             "content": run_tool(call.function.name, call.function.arguments, lead)})
    return "Sorry, could you rephrase that?", message


def run_tool(name: str, arguments: str, lead) -> str:
    try:
        args = json.loads(arguments or "{}")
    except json.JSONDecodeError:
        args = {}
    if name != "contact_team":
        return f"Unknown tool {name}"
    lead.wants_contact = True
    lead.reason = args.get("reason", "")
    if not lead.email:
        return "Saved. Ask the visitor for their email address."
    return "Passed to the team. Say someone will be in touch."


def after_reply(tenant: Tenant, conversation_id: str, stored: str, reply: str, stores) -> None:
    """Runs after the response: store the turn, email the team if due."""
    stores.conversations.append_turn(tenant.tenant_id, conversation_id, stored, reply)
    lead = stores.leads.get(tenant.tenant_id, conversation_id)
    if lead.email and lead.wants_contact and not lead.emailed:
        print(f"EMAIL to {tenant.team_email}: reply-to {lead.email}")  # Resend in the real project
        lead.emailed = True

Walk through generate_reply and match each part to the real orchestrator:

  1. Email out first: found, stored lowercase on the lead, replaced with [email provided] before anything else sees the message.
  2. Messages in order: rules → facts (all of them, verbatim) → retrieved extracts with heading paths → a note if the email is already known → history → the new message.
  3. Tool loop: at most 3 rounds; append the assistant's tool-call message as received, run each tool, append a tool message per call with its tool_call_id, call again.
  4. The tool only records; the email is decided in after_reply, which runs after the response.

Explain it: why doesn't contact_team send the email itself? (Phase 4b, §7 and challenge 5: the visitor shouldn't wait, and the summary should include the stored turn.)

Step 8. The API: site keys, domains, 503s, background work

Now replace minichat/main.py with the full version:

import uuid
from types import SimpleNamespace

from fastapi import BackgroundTasks, Depends, FastAPI, Header, HTTPException, Request
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel, Field

from minichat.agent import after_reply, generate_reply
from minichat.llm import LLMError
from minichat.models import Tenant
from minichat.stores import FactStore, InMemoryConversationStore, InMemoryTenantStore, LeadStore


class ChatRequest(BaseModel):
    message: str = Field(min_length=1, max_length=2000)
    conversation_id: str | None = Field(default=None, pattern=r"^[A-Za-z0-9-]{1,64}$")


class ChatResponse(BaseModel):
    reply: str
    conversation_id: str


def get_tenant(request: Request, x_site_key: str = Header(...),
               origin: str | None = Header(default=None)) -> Tenant:
    tenant = request.app.state.stores.tenants.get_by_site_key(x_site_key)
    if tenant is None:
        raise HTTPException(status_code=401, detail="Invalid site key")
    if origin:
        host = origin.split("://", 1)[-1].split("/", 1)[0].split(":", 1)[0].lower()
        if not any(host == d or host.endswith("." + d) for d in tenant.allowed_domains):
            raise HTTPException(status_code=403, detail="This domain is not allowed")
    return tenant


def create_app(stores=None) -> FastAPI:
    app = FastAPI(title="minichat")
    app.state.stores = stores or SimpleNamespace(
        tenants=InMemoryTenantStore(), conversations=InMemoryConversationStore(),
        facts=FactStore(), leads=LeadStore(), vectors=None,
    )
    app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_methods=["GET", "POST", "OPTIONS"],
                       allow_headers=["Content-Type", "X-Site-Key"])

    @app.get("/health")
    def health():
        return {"status": "ok"}

    @app.post("/chat", response_model=ChatResponse)
    def chat(body: ChatRequest, request: Request, background: BackgroundTasks,
             tenant: Tenant = Depends(get_tenant)) -> ChatResponse:
        stores = request.app.state.stores
        conversation_id = body.conversation_id or str(uuid.uuid4())
        try:
            reply, stored = generate_reply(tenant, conversation_id, body.message, stores)
        except LLMError as exc:
            raise HTTPException(status_code=503, detail=exc.user_message) from exc
        background.add_task(after_reply, tenant, conversation_id, stored, reply, stores)
        return ChatResponse(reply=reply, conversation_id=conversation_id)

    return app

Every idea here is from Phases 1 and 4a, in miniature: Pydantic validation with a length limit and an id pattern; a get_tenant dependency that maps a public site key to a tenant and checks Origin against allowed domains with a dot boundary; CORS open at the middleware layer; LLMError → 503; storing and emailing as a background task. SimpleNamespace is a quick object with named attributes, standing in for the nine separate store parameters of the real create_app.

Notice the line app = create_app() is gone: the run script in step 11 builds the app with its stores and starts uvicorn itself (uvicorn.run(create_app(stores), ...)).

Explain it: why is CORS * but the domain still checked? (Phase 1, §9: the preflight can't know the tenant; the dependency can.)

Step 9. Tests with a fake model

tests/test_minichat.py:

from types import SimpleNamespace
from unittest.mock import MagicMock, patch

import pytest
from fastapi.testclient import TestClient

def fake_embed(texts):
    """Word-count vectors over a tiny vocabulary: enough to rank by overlap."""
    vocab = ["food", "meals", "fees", "price", "anatomy", "body"]
    return [[t.lower().count(w) for w in vocab] for t in texts]


def text_reply(content):
    m = MagicMock()
    m.content, m.tool_calls = content, None
    return m


def tool_reply():
    call = MagicMock()
    call.id = "c1"
    call.function.name = "contact_team"
    call.function.arguments = '{"reason": "wants a call"}'
    call.model_dump.return_value = {"id": "c1", "type": "function",
                                    "function": {"name": "contact_team", "arguments": call.function.arguments}}
    m = MagicMock()
    m.content, m.tool_calls = None, [call]
    return m

def test_email_is_removed_and_contact_request_emails_once(client, stores, capsys):

    assert [c.heading_path for c in chunks] == [["A"], ["A", "B"], ["A", "B", "C"], ["A", "D"]]

The techniques are exactly Sitechat's (Phase 7, §3): in-memory stores injected into create_app; patch("minichat.llm.complete_with_tools", ...) returning MagicMock messages with chosen content or a tool call; a fake embed that counts words, enough to rank chunks; capsys to capture what was printed (the "email").

A bug met while writing this test

The first version of the email test stored the messages list each time the fake model was called, then checked the first call's last message. It failed: the agent keeps appending to the same list across tool rounds, so by the end the "first call's" list held the tool messages too. The fix was storing a copy, seen.append(list(messages)). Python lists are passed by reference; anything that keeps a list for later should copy it. (Sitechat's _run_with_tools makes its own copy, conversation = list(messages), for the same reason.)

Step 10. A widget in 60 lines

static/widget.js:

(function () {
  "use strict";
  var script = document.currentScript;
  var siteKey = script.getAttribute("data-site-key");
  var API = new URL(script.src).origin;
  var conversationId = localStorage.getItem("minichat:" + siteKey);

  var host = document.createElement("div");
  var shadow = host.attachShadow({ mode: "open" });
  var style = document.createElement("style");
  style.textContent =
    ".box{position:fixed;bottom:20px;right:20px;width:320px;font:15px/1.5 inherit;" +
    "background:#fff;border:1px solid #ddd;border-radius:12px;padding:12px}" +
    ".log{height:260px;overflow:auto;display:flex;flex-direction:column;gap:8px}" +
    ".me{align-self:flex-end;background:#1f6f5c;color:#fff}.me,.bot{padding:8px 10px;border-radius:10px}" +
    ".bot{background:#f2f4f3}";
  shadow.appendChild(style);

  var box = document.createElement("div");
  box.className = "box";
  var log = document.createElement("div");
  log.className = "log";
  var input = document.createElement("input");
  input.placeholder = "Ask a question";
  input.setAttribute("aria-label", "Your message");
  box.appendChild(log);
  box.appendChild(input);
  shadow.appendChild(box);
  document.body.appendChild(host);

  function add(who, text) {
    var p = document.createElement("p");
    p.className = who;
    p.textContent = text;          // text, never HTML
    log.appendChild(p);
    log.scrollTop = log.scrollHeight;
  }

  input.addEventListener("keydown", function (e) {
    if (e.key !== "Enter" || !input.value.trim()) return;
    var text = input.value.trim();
    input.value = "";
    add("me", text);
    var body = { message: text };
    if (conversationId) body.conversation_id = conversationId;
    fetch(API + "/chat", {
      method: "POST",
      headers: { "Content-Type": "application/json", "X-Site-Key": siteKey },
      body: JSON.stringify(body),
    })
      .then(function (r) {
        if (!r.ok) throw new Error(String(r.status));
        return r.json();
      })
      .then(function (data) {
        conversationId = data.conversation_id;
        localStorage.setItem("minichat:" + siteKey, conversationId);
        add("bot", data.reply);
      })
      .catch(function () { add("bot", "That did not get through. Try again."); });
  });
})();

The essentials of Phase 5: an IIFE so nothing leaks into the page; the site key and API address from its own script tag; a shadow root so the page's CSS can't reach in; textContent only, never innerHTML; the conversation id in localStorage. Checked in Chromium against minichat on a local port, cross-origin, with a fake model replying <b>Hello</b> from the bot. Real output:

['hi', '<b>Hello</b> from the bot']
bold tag rendered as element? 0

The tags arrived as visible text and created no element: the XSS defence working.

To serve it, add to create_app in main.py: from fastapi.staticfiles import StaticFiles and app.mount("/static", StaticFiles(directory="static"), name="static"), then put <script src="http://localhost:8080/static/widget.js" data-site-key="pk_1"></script> on any HTML page.

Step 11. Run it for real

With an OpenAI key, a small script sets up a tenant, some facts and a document, then starts the server. Save as run.py next to the minichat/ folder:

import os
from types import SimpleNamespace

import uvicorn

from minichat.main import create_app
from minichat.models import Fact, Tenant
from minichat.retrieval import InMemoryVectorStore, chunk_markdown
from minichat.stores import FactStore, InMemoryConversationStore, InMemoryTenantStore, LeadStore

assert os.environ.get("OPENAI_API_KEY"), "set OPENAI_API_KEY first"

stores = SimpleNamespace(tenants=InMemoryTenantStore(), conversations=InMemoryConversationStore(),
                         facts=FactStore(), leads=LeadStore(), vectors=InMemoryVectorStore())
stores.tenants.save(Tenant(tenant_id="demo", site_key="pk_1", display_name="Demo Yoga School",
                           allowed_domains=["localhost", "127.0.0.1"], team_email="you@example.com"))
stores.facts.save("demo", [Fact(category="Fees", label="200-hour course", value="USD 1,450 with meals")])
stores.vectors.add("demo", chunk_markdown(
    "# Demo Yoga School\n## Food\nThree vegetarian meals a day.\n## Rooms\nShared twin rooms.",
    "demo", "about"))

uvicorn.run(create_app(stores), host="127.0.0.1", port=8080)

In PowerShell: $env:OPENAI_API_KEY = "sk-..." then python run.py. Then try it from a second terminal:

To keep the conversation going, add "conversation_id": "..." from the first reply.

Ask about food (from the document), fees (from the facts), something not covered (it should say it doesn't know), and "please have someone contact me, me@example.com" (watch the terminal print the "email"). Each real call costs a fraction of a cent.
