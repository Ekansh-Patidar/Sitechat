You're sharing the Sitechat folder with someone, without your .env file. This phase is written for them, and for you before you send it. 1. Part A (sender): what to share and what never to share

The project folder on your computer contains more than the code. Some of it is secret, some is visitors' personal data, some is just bulky. Here is every top-level item:

ItemShare?Why
.envNeverYour API keys. Anyone with them can spend on your OpenAI account and read or change your databases.
service-account.jsonNeverA private key for a Google service account that can read your schools' Google Sheets. If it's ever sent by mistake, delete that key in Google Cloud (IAM → Service accounts → Keys) at once.
chat.txtNoA dump of real conversations (visitor data). Gitignored for that reason.
leads-*.csvNoVisitors' names, emails and phone numbers, if you've exported any.
.venv/NoYour Python environment: large, specific to your machine (and on Python 3.14). They create their own.
__pycache__/, .pytest_cache/, .mypy_cache/, .ruff_cache/NoGenerated caches.
docs/Your choiceThe school's documents and programmes.yaml. Not secret (they're from the school's public website) but the school's content; needed for the Level 2 demo to answer about real courses. Gitignored, so it isn't in git.
evaluation/history/OptionalSaved evaluation runs; not needed to run anything.
.claude/OptionalYour Claude Code settings for this project.
.git/YesThe full history (useful to read the commit messages). gitleaks has scanned it: no secrets were ever committed.
Everything elseYesThe code, tests, notes and configuration.

The safe way to package it

git archive includes only files tracked by git, so every ignored file (.env, service-account.json, chat.txt, .venv, docs/...) is left out automatically. From the project folder, in PowerShell or Git Bash:

git archive --format=zip -o sitechat.zip HEAD

If you also want to send the documents for the Level 2 demo, zip docs\pyramid-yogshala separately. Or push the repo to GitHub and give them access, which also gives them the history.

Two things inside the code that are yours

  • scripts/create_tenant.py contains your email as the tenant's team_email, and your Google Sheet's id. Harmless to share (they can't access your sheet without being shared on it), but they should replace both with their own before running it.
  • Several notes and docstrings name your Google Cloud project (sitechat-511008) and your service URL. They're documentation; the recipient substitutes their own. Nothing in the running code depends on them except the defaults listed in section 7.

3. Part C, Level 1: run the tests

Needs: Python 3.12 and Git (optional). Time: 10 minutes. Accounts: none.

  1. Install Python 3.12 from python.org (Windows: tick "Add python.exe to PATH"). The project, its CI and its container all use 3.12. Newer versions mostly work (the sender's machine runs 3.14), but 3.12 avoids surprises.
  2. Unzip the folder and open a terminal in it (the folder containing CLAUDE.md).
  3. Create and activate a virtual environment: 
    # Windows (PowerShell)
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
# If PowerShell refuses to run the activation script, run once:
#   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# macOS / Linux
python3.12 -m venv .venv
source .venv/bin/activate
    Your prompt now starts with (.venv).
  4. Install the dependencies: 
    pip install -r requirements-dev.txt
    This installs the service's packages plus pytest, ruff, mypy, bandit and coverage, at the exact versions the project uses.
  5. Run the tests: 
    # Windows (PowerShell)
$env:ENVIRONMENT = "development"; $env:GCP_PROJECT_ID = "test-project"
pytest

# macOS / Linux
ENVIRONMENT=development GCP_PROJECT_ID=test-project pytest
    The two variables match what CI sets. (Checked: the suite also passes with neither set and no .env, since both have safe defaults, but setting them keeps you identical to CI.)

What success looks like (real output from a clean copy with no .env, browser tests excluded):

451 passed, 5 warnings in 17.67s

With Playwright installed, the browser tests run too and the total is 492. To include them:

pip install playwright
python -m playwright install chromium webkit
pytest tests/browser

The other CI checks, if you want to run them all:

ruff check .
mypy
bandit -q -r app scripts --skip B101
pytest --cov=app --cov-fail-under=80
Why this works with no keys

Every test uses in-memory stores and a scripted stand-in for the AI (Phase 7, §3). Nothing in the suite touches the internet.

4. Part D, Level 2: run the chat locally with only an OpenAI key

Needs: Level 1, plus an OpenAI API key with billing set up (platform.openai.com → API keys). Time: 10 minutes.

The normal way to start the server, uvicorn app.main:app, connects to Google Firestore at start-up. Without Google credentials it stops with this (real error from a clean copy):

google.auth.exceptions.DefaultCredentialsError: Your default credentials were not found.
To set up Application Default Credentials, see https://cloud.google.com/docs/authentication/external/set-up-adc for more information.

So for a local demo, use a small script that builds the app with in-memory stores instead, exactly the way the tests do (create_app(...) with every store supplied, so lifespan creates nothing in the cloud). Only OpenAI is real. Save this as local_demo.py in the project folder (next to CLAUDE.md):

"""Run Sitechat on this computer with no Google Cloud and no Pinecone.

    python local_demo.py

Everything is kept in memory (lost when you stop it). Only OpenAI is real,
so OPENAI_API_KEY must be set in .env or the environment. Documents in
docs/<tenant>/ are embedded at start-up (a fraction of a cent). No email is
sent: without a Resend key, a request for the team makes the bot give the
contact details instead.

Then open http://localhost:8080/widget/test-page.html
"""

import os
from pathlib import Path

os.environ.setdefault("ENVIRONMENT", "development")
os.environ.setdefault("GCP_PROJECT_ID", "local")

import uvicorn  # noqa: E402

from app.config import get_settings  # noqa: E402
from app.conversations.store import InMemoryConversationStore  # noqa: E402
from app.documents.ingest import ingest_file  # noqa: E402
from app.documents.store import InMemoryChunkStore  # noqa: E402
from app.facts.models import Fact, FactSheet  # noqa: E402
from app.facts.store import InMemoryFactStore  # noqa: E402
from app.feedback.store import InMemoryFeedbackStore  # noqa: E402
from app.leads.store import InMemoryLeadStore  # noqa: E402
from app.main import create_app  # noqa: E402
from app.programmes.models import load_catalogue  # noqa: E402
from app.programmes.store import InMemoryProgrammeStore  # noqa: E402
from app.retrieval.vector_store import InMemoryVectorStore  # noqa: E402
from app.tenants.models import Tenant  # noqa: E402
from app.tenants.store import InMemoryTenantStore  # noqa: E402
from app.usage.store import InMemoryUsageStore  # noqa: E402

TENANT_ID = "pyramid-yogshala"
DOCS = Path("docs") / TENANT_ID

if not get_settings().openai_api_key.get_secret_value():
    raise SystemExit("Set OPENAI_API_KEY in .env first (see Phase 10, step 2).")

tenants = InMemoryTenantStore()
tenants.save(Tenant(
    tenant_id=TENANT_ID,
    site_key="pk_pyramid_yogshala_001",          # the key static/test-page.html uses
    display_name="Pyramid Yogshala",
    allowed_domains=["localhost", "127.0.0.1"],
    greeting="Namaste! Ask me anything about our courses.",
    suggested_questions=["What food is provided?", "Who are the teachers?"],
))

facts = InMemoryFactStore()
facts.save(FactSheet(tenant_id=TENANT_ID, facts=[
    Fact(category="Courses and fees", label="200-hour Teacher Training fee",
         value="USD 1,450, including shared accommodation and all meals"),
]))

chunks, vectors, programmes = InMemoryChunkStore(), InMemoryVectorStore(), InMemoryProgrammeStore()
if DOCS.is_dir():
    catalogue = None
    if (DOCS / "programmes.yaml").is_file():
        catalogue = load_catalogue(DOCS / "programmes.yaml", TENANT_ID)
        programmes.save(catalogue)
    for path in sorted(DOCS.glob("*.md")):
        result = ingest_file(path, TENANT_ID, chunks, vectors, catalogue)
        print(f"  {result.title}: {result.chunk_count} chunks")
else:
    print(f"No {DOCS} folder: the bot will answer from the facts only.")

app = create_app(
    tenant_store=tenants,
    conversation_store=InMemoryConversationStore(),
    fact_store=facts,
    vector_store=vectors,
    chunk_store=chunks,
    lead_store=InMemoryLeadStore(),
    programme_store=programmes,
    usage_store=InMemoryUsageStore(),
    feedback_store=InMemoryFeedbackStore(),
)

if __name__ == "__main__":
    print("Open http://localhost:8080/widget/test-page.html")
    uvicorn.run(app, host="127.0.0.1", port=8080)
  1. Create .env in the project folder with one line (no quotes): 
    OPENAI_API_KEY=sk-your-key-here
    .env is gitignored, so it can't be committed by accident.
  2. Put the documents in place (if the sender included them): docs\pyramid-yogshala\ with the three .md files and programmes.yaml. Without them the bot still runs, answering from the one fact in the script.
  3. Start it: python local_demo.py. It prints each document as it's embedded: 
      200-Hour Hatha, Ashtanga, Naturopathy and Ayurveda Yoga Teacher Training: 18 chunks
  Pyramid Yogshala: Courses, Retreats and School Information: 58 chunks
  Pyramid Yogshala: The School and the Rishikesh Campus: 19 chunks
Open http://localhost:8080/widget/test-page.html
  4. Open http://localhost:8080/widget/test-page.html. That page is deliberately styled to be hostile to the widget (dashed red buttons, yellow textareas); the widget should look normal anyway. Click the chat button and ask "What food is provided?".

Checked with a scripted model and stand-in embeddings: the page loads (200), /config returns the tenant's settings, and /chat returns a reply with a conversation id. With a real key, answers come from the school's documents.

What's different from production: nothing is saved (stop the script and the conversations are gone); no lead email (without a Resend key, asking for the team makes the bot give the business's contact details instead); no daily facts sync or digest. Everything else (retrieval, programme focus, the prompt, the tools, the widget) is the real code.

E3. Google Cloud from the command line

Install the Google Cloud CLI (cloud.google.com/sdk), then:

gcloud auth login
gcloud config set project your-project-id
gcloud auth application-default login       # lets code on your computer use Firestore as you

gcloud services enable firestore.googleapis.com sheets.googleapis.com
gcloud firestore databases create --location=us-central1

application-default login creates the "Application Default Credentials" whose absence caused the error in Level 2. After it, uvicorn app.main:app can start. us-central1 matches where the project's server runs; keep the database and server in the same region.

E4. The Pinecone index (once)

python -m scripts.create_index

Creates the index named by PINECONE_INDEX_NAME (1,536 dimensions, cosine, AWS us-east-1), or does nothing if it exists.

E5. Create your tenant

Edit the values in scripts/create_tenant.py first:

  • team_email: your own address (it's the sender's today).
  • allowed_domains: keep localhost and 127.0.0.1; replace the Cloud Run host with yours after Level 4.
  • facts_sheet_id: your sheet's id (step E7) or "" for none.
  • Keep site_key="pk_pyramid_yogshala_001" if you want static/test-page.html to work unchanged; if you change it, change the key in the test page too.
python -m scripts.create_tenant

E6. Load the documents

python -m scripts.ingest pyramid-yogshala docs/pyramid-yogshala
python -m scripts.inspect_chunks pyramid-yogshala            # see what was stored

Ingest embeds every chunk (paid, cents) and stores text in Firestore and vectors in Pinecone. Expect 95 chunks for the school's three documents. Any line printed as "CHECK, reads like an instruction to the bot" deserves a look.

E7. Load the facts

Two options:

  • Quick: edit the list in scripts/set_facts.py and run python -m scripts.set_facts.
  • As the real product does, from a Google Sheet:
    1. Create a sheet with headers Category, Label, Value in row 1, one fact per row.
    2. Create a service account for reading it: gcloud iam service-accounts create sheets-reader, then in the console create a JSON key for it and save it as service-account.json in the project folder (gitignored; never share it).
    3. Share the sheet with that account's email address as Viewer.
    4. Put the sheet's id (the long part of its URL between /d/ and /edit) in facts_sheet_id in create_tenant.py, re-run it, then: python -m scripts.sync_facts pyramid-yogshala. It prints what was added and any rows it skipped, with reasons.

E8. Run the full system locally

uvicorn app.main:app --reload --port 8080

Open http://localhost:8080/widget/test-page.html. Now conversations are saved in your Firestore, retrieval uses your Pinecone index, and with a Resend key a contact request sends a lead email to team_email. Check your data with python -m scripts.dump_conversation pyramid-yogshala.

E9. Measure it (optional, paid)

python -m scripts.evaluate pyramid-yogshala            # retrieval; embeddings only
python -m scripts.evaluate_answers pyramid-yogshala    # answers + judge; a few cents
python -m scripts.evaluate_attacks pyramid-yogshala    # 29 attacks; a few cents

6. Part F, Level 4: deploy to Cloud Run

Needs: Level 3, the code in a GitHub repository you control. Time: about an hour. Each step below has a full guide in notes/; replace sitechat-511008 in them with your project id.

  1. Enable the services: 
    gcloud services enable run.googleapis.com cloudbuild.googleapis.com artifactregistry.googleapis.com secretmanager.googleapis.com cloudscheduler.googleapis.com
  2. Create the image repository: 
    gcloud artifacts repositories create sitechat --repository-format=docker --location=us-central1
  3. Create the secrets, one per key, from a file or standard input (PowerShell example for one; repeat for each you use): 
    "sk-your-key" | Out-File -NoNewline -Encoding ascii key.txt
gcloud secrets create OPENAI_API_KEY --data-file=key.txt
Remove-Item key.txt
    cloudbuild.yaml's --set-secrets line lists five secrets: OPENAI_API_KEY, PINECONE_API_KEY, COHERE_API_KEY, RESEND_API_KEY, SENTRY_DSN. Every secret named there must exist or the deploy fails. If you don't use Cohere, Resend or Sentry, delete those entries from that line rather than creating placeholder secrets (a placeholder Sentry DSN would be an invalid DSN at start-up). tests/test_cloudbuild.py checks that each listed secret is granted in the setup notes, so keep the two in step.
  4. Create the runtime service account and its permissions: follow notes/runtime-sa-setup.md steps 1 to 4 (create sitechat-runtime; grant roles/datastore.user; grant roles/secretmanager.secretAccessor on each secret you created; let your build account act as it). Do this before the first deploy, or the deploy step fails (safely: nothing changes).
  5. Create the Cloud Build trigger: in the console, Cloud Build → Triggers → Connect repository (GitHub) → Create trigger on pushes to main, using the cloudbuild.yaml in the repo. A trigger is needed rather than a manual gcloud builds submit, because built-in values like $SHORT_SHA (used to tag the image) are filled in only for builds started from a connected repository.
  6. Push to main. The build runs the tests (about 45 s), builds and pushes the image, and deploys. The deploy output prints the service URL (https://sitechat-api-...run.app).
  7. Allow the new host: add the service's host name to allowed_domains in create_tenant.py, re-run it, then check the deployment: 
    python -m scripts.smoke_test https://your-service-url pk_pyramid_yogshala_001
    Expected: ok /health and ok /config (Pyramid Yogshala). Then open https://your-service-url/widget/test-page.html.
  8. The 5-minute job (lead digest and daily facts sync): follow notes/lead-digest-setup.md with your service URL. It creates the lead-digest service account and the Cloud Scheduler job. cloudbuild.yaml already sets LEAD_DIGEST_INVOKER to lead-digest@$PROJECT_ID..., so it works for your project. For the daily facts sync in production, share each facts sheet with sitechat-runtime@your-project-id.iam.gserviceaccount.com as Viewer.
  9. Automatic deletion of old data: the three commands in notes/retention-setup.md (TTL on expire_at for conversations, leads and feedback).
  10. Installing on a real site: notes/install-guide.md, with your service URL in the snippet and the site's domain added to allowed_domains.

ModuleNotFoundError: No module named 'app'Run commands from the project folder (the one with CLAUDE.md), and run scripts as python -m scripts.name, not python scripts/name.py.

9. Challenges we faced while setting it up

Real setup problems from the project's history, so the recipient recognises them:

Tests that only passed on the developer's machine

Three times, tests passed locally because .env had keys, and failed on GitHub where it didn't. Now the suite needs no keys at all, which is why Level 1 works on a fresh machine. Checked for this guide by running it in a clean copy with no .env.

A missing space in a gcloud command

A secret's access grant silently never happened because SENTRY_DSN--member=... was typed without a space, and the next deploy failed on permissions. Copy commands exactly, and read what a command reports.

An account Google creates later

The default compute service account didn't exist yet; Google creates it the first time the Compute Engine API is enabled. If a setup step names an account that doesn't exist, check which API creates it.

Requirements files in UTF-16

Regenerating requirements.txt with PowerShell's > wrote UTF-16, which pip can't read. Both files are UTF-8; the comment at the top of requirements.txt warns about it.

Different Python versions

The sender's machine runs 3.14 while everything else runs 3.12. Installing 3.12 for the recipient avoids "works on my machine" surprises; the Cloud Build test step guarantees 3.12 before any deploy.

Order matters for the service account

Deploying with --service-account=sitechat-runtime@... before creating that account fails the deploy step. The setup notes say to run the account steps first; the failure is safe (the old revision keeps serving).

Check yourself

Which two files must never be shared, and what should you do if one is?

.env (API keys) and service-account.json (a Google private key). Rotate the leaked keys: create new API keys and revoke the old ones; delete the service account key in IAM.

Why does git archive make a safe package?

It includes only files tracked by git; everything in .gitignore (secrets, visitor data, environments, docs) is left out.

Why can the tests run with no accounts at all?

They inject in-memory stores and a scripted model, so nothing reaches Firestore, Pinecone or OpenAI.

Why does uvicorn app.main:app fail without Google credentials, and how does local_demo.py avoid it?

The lifespan builds Firestore stores for any store not supplied, which needs credentials. local_demo.py supplies every store as an in-memory one, so the lifespan builds nothing.

A deploy fails because SENTRY_DSN doesn't exist. What are your two options?
